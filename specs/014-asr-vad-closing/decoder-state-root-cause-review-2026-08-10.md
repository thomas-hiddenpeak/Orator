## Concrete Decoder-Contract Mismatch

The pinned official vLLM path constructs `SamplingParams` with only
`temperature = 0.0` and `max_tokens`. It does not set a minimum token count,
ignore EOS, or suppress either EOS token during the first decode steps.

The native `AsrTextDecoder::DecodeGreedy`, however, passes both EOS IDs to
`ArgmaxBanned` for the first `ban_steps` argmax positions. The checked-in typed
TOML value is `ban_steps = 3`, and it flows unchanged through
`AuditoryStream::Config` and `AsrConfig`. This is a concrete decoder-termination
contract difference, not a transcript-derived parameter guess. The TOML comment
describing it as a repetitive n-gram control is also inaccurate; the
implementation suppresses EOS.

The native decoder additionally stops after six identical emitted token IDs,
which is not explicit in the pinned official sampling configuration. None of
the 91 recorded continuations ends in six identical IDs, so that guard did not
activate in this evidence and does not authorize a second change.

The current trace records emitted IDs after banned argmax and therefore cannot
show whether EOS was the unsuppressed top token in any particular row. Removing
the ban is consequently a bounded official-contract experiment, not a claim
that the mismatch caused all observed substitutions.
